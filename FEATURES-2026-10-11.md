# SubnetDesk Helper: requested improvements

Implemented requests 1, 2, 4, 5 and 7 in the existing checkout on 2026-10-11.

## Available behavior

1. **Check connection:** available in each device menu, the desktop connection
   dialog, the desktop toolbar and the phone connection page. Supports IP/DNS,
   custom ports and IPv6. Reports invalid input, DNS failure, refused connections,
   timeout or reachable TCP port. The probe sends no credentials; success does
   not establish device identity or authenticate a session. A timeout does not
   identify a firewall as the definite cause.
2. **Devices:** discovered devices can be renamed; aliases survive refresh.
   Existing favorite groups are searchable alongside names, hostnames and IPs.
   Recent/favorite device cards show the last successful connection and can be
   sorted by it. Online sorting now has a valid comparator. Favorites include
   devices starred before their first successful connection.
4. **Permissions at acceptance:** manual screen requests default to viewing.
   Control, clipboard and files require explicit selection. File-only requests
   cannot be accepted without file permission. Terminal/forwarding requests need
   explicit approval of their requested access. Permissions are applied before
   backend authorization and cannot expand transport restrictions. Restart,
   recording, input blocking and privacy mode are not granted by this chooser.
   Password/code authentication retains its existing policy.
5. **Receiver/session status:** the desktop connection page displays the actual
   receiver service state and the authorized-session count, including file
   sessions. Service failure details are available in the status tooltip. The
   incoming-session dock has a visible Disconnect button using the existing
   local-click protection and silencing the selected session's ringtone.
7. **Android file sharing:** select one or more files in another app, choose
   SubnetDesk, then Choose computer and authenticate. Select a destination folder
   and press Send here. Shared content URIs are streamed into an app-owned folder;
   no broad storage permission is added. The inbox survives activity recreation.
   Progress displays filename, percentage and speed. Failed transfers can be
   retried with a fresh job ID. Cancelling one transfer keeps other jobs visible.
   Import errors are shown; batches above 100 files report the limit explicitly.
